# Развёртывание на общем Windows VPS

## Выбранная схема

African Villas разворачивается как независимый сервис:

- адрес: `https://villas.bimplatforma.ru`;
- DNS: отдельная A-запись на `62.113.36.107`;
- приложение: `127.0.0.1:8092`, один процесс Uvicorn;
- HTTPS и публичный вход: существующий Caddy;
- файлы: `C:\AfricanVillas`;
- база: отдельная SQLite в `C:\AfricanVillas\runtime\data`;
- запуск и резервное копирование: отдельные задачи `AfricanVillasWeb` и `AfricanVillasBackup`.

Проект не использует PostgreSQL платформы и не занимает порты Platform (`8090`), analysis-worker (`8091`), Connector (`8080`) или FamilyBudget (`3001`). Он не требует изменений IIS, Revit Server или Tekla License Server.

## Что скрипт установки меняет

`infra\windows\install-service.ps1` создаёт только `C:\AfricanVillas` и две задачи планировщика с префиксом `AfricanVillas`. Каждый релиз получает собственное виртуальное окружение в `C:\AfricanVillas\releases`. Перед переключением выполняется согласованный SQLite-бэкап, а при неуспешном локальном health check указатель возвращается на предыдущий релиз.

Скрипт намеренно не меняет DNS, Caddy, Windows Firewall, IIS, PostgreSQL и чужие задачи/службы.

## Секреты

При первом запуске установщик создаёт `C:\AfricanVillas\runtime\config.production.json` из шаблона и завершает работу до регистрации задач. Нужно вручную задать:

- длинный уникальный `WebPassword`;
- случайный `SessionSecret` длиной не менее 32 байт;
- `CodexAuthMode`: `chatgpt` для использования подписки или `api` для оплаты через OpenAI Platform;
- `OpenAIApiKey` требуется только при режиме `api`.

Конфигурация не входит в Git. Установщик ограничивает ACL файла системной учётной записью и локальными администраторами. Само выполнение Codex не публикуется напрямую — снаружи доступно только приложение с авторизацией.

По умолчанию выбран режим `chatgpt`. Для African Villas создаётся отдельный `C:\AfricanVillas\runtime\codex-home`, не связанный с авторизациями других программ сервера. Кэш входа хранится файлом с ACL только для `SYSTEM` и локальных администраторов, чтобы фоновая задача могла обновлять токен.

После первой установки нужно один раз выполнить в интерактивной PowerShell-сессии администратора:

```powershell
C:\AfricanVillas\runtime\login-codex.ps1
```

Скрипт покажет адрес и одноразовый код. Адрес открывается в любом браузере, вход подтверждается учётной записью ChatGPT с подпиской. Состояние можно проверить без нового входа:

```powershell
C:\AfricanVillas\runtime\login-codex.ps1 -StatusOnly
```

Если device-code login отключён в настройках ChatGPT, его нужно разрешить в Security settings. При отзыве сессии или выходе из аккаунта интерактивный вход потребуется повторить.

## Порядок первого запуска

1. Создать DNS A-запись `villas.bimplatforma.ru -> 62.113.36.107` и дождаться разрешения имени.
2. Передать проверенную копию исходников на VPS во временный каталог релиза.
3. Запустить PowerShell от администратора:

   ```powershell
   .\infra\windows\install-service.ps1 -InstallRoot C:\AfricanVillas
   ```

4. Заполнить созданный `C:\AfricanVillas\runtime\config.production.json` и повторить команду.
5. При `CodexAuthMode = chatgpt` выполнить `C:\AfricanVillas\runtime\login-codex.ps1` и подтвердить одноразовый код в браузере.
6. Проверить локально:

   ```powershell
   .\infra\windows\health-check.ps1
   ```

7. Сделать резервную копию действующего файла Caddy, добавить блок из `infra\windows\Caddyfile.snippet`, затем выполнить `caddy validate` и штатный `caddy reload` с фактическим путём конфигурации.
8. Проверить вход по HTTPS и повторно проверить health endpoints Platform, analysis-worker, Connector и FamilyBudget, а также состояние IIS, Revit и Tekla.

Пункты 1, 2, 7 и 8 требуют проверки фактической конфигурации VPS непосредственно перед выполнением. Добавление Caddy-маршрута выполняется только после явного подтверждения владельца сервера.

## Обновление и откат

Штатные обновления выполняет GitHub Actions workflow `.github/workflows/deploy-production.yml`.
Он запускается только после успешного workflow `Tests` для `push` в `main` либо вручную с ветки
`main`. Pull request не получает доступ к продакшен-секретам и не может развернуть код.

В репозитории нужно создать GitHub Environment `production` и настроить:

- обязательное подтверждение владельца перед каждым деплоем;
- разрешение деплоя только из `main`;
- переменные `PROD_HOST` и `PROD_SSH_USER`;
- секрет `PROD_SSH_PRIVATE_KEY` с отдельным ключом только для автоматического деплоя;
- секрет `PROD_SSH_KNOWN_HOSTS` с заранее проверенной строкой host key VPS.

Приватный ключ обычного администратора, пароль Windows, веб-пароль, `SessionSecret` и кэш входа
ChatGPT в GitHub не передаются. Деплой использует GitHub-hosted Windows runner; на общем VPS не
устанавливается self-hosted runner, который мог бы выполнять произвольный код репозитория как
постоянная служба.

Workflow заново прогоняет тесты, собирает wheel и ZIP с `manifest.json`, привязанным к точному
commit SHA. После загрузки сервер проверяет SHA-256 ZIP и соответствие commit в манифесте. Затем
`deploy-artifact.ps1` запускает тот же `install-service.ps1`. Он:

1. собирает новое изолированное окружение, не трогая работающий процесс;
2. делает бэкап данных;
3. останавливает только `AfricanVillasWeb`;
4. переключает `current-release.txt` и запускает новый релиз;
5. при провале `/health` возвращает предыдущий указатель и запускает прежний релиз.

Первый bootstrap выполняется вручную по SSH: он создаёт защищённую конфигурацию, задачи
планировщика и `C:\AfricanVillas\runtime\deploy-artifact.ps1`. Все последующие релизы должны идти
через GitHub Environment, чтобы в GitHub сохранялась однозначная история «commit → deployment».

Ежедневный бэкап в 03:30 сохраняет согласованный снимок SQLite и загруженные документы в `C:\AfricanVillas\runtime\backups`. Кэш и временные файлы в архив не входят; срок хранения по умолчанию — 30 дней.

## Контроль после публикации

- `http://127.0.0.1:8092/health` должен отвечать `ok: true`;
- порт `8092` не должен слушать внешний интерфейс;
- `https://villas.bimplatforma.ru` должен перенаправлять на форму входа и иметь валидный сертификат;
- конфигурация и логи не должны содержать секреты в Git или публичных ответах;
- после перезагрузки VPS задачи `AfricanVillasWeb` и `AfricanVillasBackup` должны оставаться активными, а соседние сервисы — отвечать как до установки.
