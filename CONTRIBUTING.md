# Совместная работа

Репозиторий разрабатывается через короткие рабочие ветки и pull request'ы. В `main` напрямую не
коммитим: она должна оставаться запускаемой и проходить автоматические тесты.

## Начало работы

```powershell
git switch main
git pull --ff-only origin main
git switch -c feature/короткое-название
```

Используем префиксы:

- `feature/` — новая возможность;
- `fix/` — исправление ошибки;
- `chore/` — инфраструктура и обслуживание;
- `docs/` — только документация.

Одна ветка и один pull request должны решать одну законченную задачу. Перед началом крупного
изменения согласуем постановку в GitHub Issue или в описании draft PR.

## Локальная проверка

Проект рассчитан на Python 3.12. Первичная настройка:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Перед отправкой изменений:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Данные проектов, PDF, кэш, `.venv` и секреты не коммитим. Исследовательские вызовы Codex могут
расходовать лимиты аккаунта и обращаться к внешним источникам, поэтому обычные тесты не должны
запускать такие вызовы.

## Pull request

1. Обновите ветку относительно свежего `main`.
2. Опишите пользовательский результат и существенные технические решения.
3. Укажите выполненные проверки и приложите снимки интерфейса, если менялся UI.
4. Дождитесь зелёного workflow `Tests` и ревью второго участника.
5. После merge удалите рабочую ветку.

Для небольших логичных изменений предпочтителен squash merge: история `main` остаётся читаемой,
а детали обсуждения сохраняются в pull request.
